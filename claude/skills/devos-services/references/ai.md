# AI engineering

First use the documentation skills or tools available for the requested provider and fetch current official guidance for the specific API/model (for Anthropic/Claude the `claude-api` skill where installed; for OpenAI the official platform documentation via WebFetch, because the Codex built-in OpenAI Docs skill has no Claude Code equivalent). Verify actual account/client availability; model names, costs and SDK parameters are not durable assumptions. Preserve the requested provider and stack. Use the provider's current documented tool-calling pattern (for example the OpenAI Responses API or Anthropic Messages API tool use); use an agent SDK (OpenAI Agents SDK, Claude Agent SDK) when orchestration, handoffs or tracing justify it.

Specify typed input/output schemas, streaming behavior, cancellation, timeout/retry policy, rate/cost limits and graceful failure. Validate structured output and tool arguments in application code. Separate developer policy, user input, retrieved content and tool output; retrieved instructions never grant authority. Scope retrieval and caches to the authorized tenant/user and cite evidence when the product requires it.

Treat every consequential tool as an authorization boundary: allowlist actions, least-privilege credentials, server-side permission checks, idempotency and action confirmation appropriate to the actual user authorization. Bind confirmation to the actor, action, resource and material arguments, not an arbitrary model-provided boolean. For real external actions make idempotency durable and test concurrent retries; an in-memory set in a mock proves neither. Never trust model output to select another user's identity, authorize a payment or form a shell command. Redact logs and prevent secrets crossing into client prompts or untrusted tools.

Build a small deterministic contract suite with mocked providers plus explicitly authorized live smoke tests. Evaluate useful success cases, ambiguous/unsupported requests, injection in retrieved documents, tool denial, malformed output, timeout/retry and cross-tenant leakage. For RAG, separate retrieval quality from answer quality. Record model/version, fixtures, latency/cost observations if measured, and limitations. A single convincing chat response does not establish reliability.
